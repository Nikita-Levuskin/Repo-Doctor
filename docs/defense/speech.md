# Текст выступления на 5-7 минут

Здравствуйте. Тема моей курсовой работы — разработка CLI-утилиты Repo Doctor для
автоматического аудита и приведения репозиториев к единому стандарту.

В реальных проектах репозитории создаются разными командами и в разное время. Поэтому в
них может отсутствовать README, лицензия, `.gitignore` или CI-конфигурация. Ручная проверка
повторяется, зависит от внимательности человека и плохо масштабируется. Цель моей работы —
разработать и проверить простую утилиту, которая обнаруживает такие отклонения и безопасно
создаёт недостающие файлы.

Я сформулировал функциональные требования: рекурсивный аудит, конфигурация YAML/JSON,
текстовый и JSON-отчёт, генерация файлов и интеграция с GitHub и GitLab. Главным
нефункциональным требованием стала безопасность. По умолчанию программа ничего не
изменяет. Для записи нужен явный флаг `--apply`, а существующий файл не перезаписывается
без дополнительного `--overwrite`.

Архитектура состоит из нескольких независимых слоёв. Typer отвечает только за команды.
Pydantic и загрузчик проверяют конфигурацию. Сканер запускает набор правил и собирает
единый отчёт. Генератор получает этот отчёт и применяет Jinja2-шаблоны. GitHub и GitLab
реализованы двумя адаптерами общего интерфейса. Такое разделение позволило тестировать
ядро без запуска CLI и проверять HTTP через mock-транспорт.

Сейчас я покажу основной сценарий. В демонстрационном репозитории есть исходный файл, но
нет стандартных служебных файлов. Команда scan находит пять нарушений: README, лицензия,
`.gitignore`, манифест и CI. Для каждого указаны уровень, путь, рекомендация и возможность
автоисправления. Команда fix с dry-run показывает план и не меняет каталог. После явного
apply создаются пять файлов. Новый scan сообщает, что нарушений нет, а повторный apply
возвращает пустой список. Это подтверждает идемпотентность.

Кроме структуры программа обнаруживает `.env`, типовые строки токенов и битые локальные
ссылки README. Поиск секретов является эвристическим: он не заменяет специализированный
secret scanner, поэтому это ограничение явно указано в документации. Бинарные и слишком
большие файлы не читаются как текст, а символические ссылки не обходятся.

Интеграция с GitHub и GitLab реализована на уровне REST API. Токен берётся только из
переменной окружения и не выводится. Dry-run формирует запрос без сети. Сама утилита не
делает commit и push: ветка должна быть опубликована отдельно. В рамках курсовой реальные
PR и MR не создавались; ответы 401, 403, 404, 409, 429, 5xx, тайм-ауты и сетевые ошибки
проверены mock-тестами.

Для приёмки проект был установлен в изолированное окружение Python 3.12. Ruff и mypy
прошли без замечаний. Все 39 тестов прошли, покрытие составило 89,72 процента при пороге
80 процентов. Пакет собран в sdist и wheel, затем wheel установлен в новое чистое
окружение. Демонстрационный цикл подтвердил отсутствие нарушений и идемпотентность.

В результате цель достигнута: создана и проверена CLI-утилита Repo Doctor. Её ограничения
состоят в эвристическом поиске секретов, минимальных универсальных шаблонах и отсутствии
фактического кроссплатформенного запуска и реального API-вызова в этой работе. Дальнейшее
развитие возможно через подключаемые правила и более широкую CI-матрицу. Спасибо за внимание.
