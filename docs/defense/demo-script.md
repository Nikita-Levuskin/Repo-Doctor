# Сценарий демонстрации

## Основной сценарий (3-4 минуты)

1. Показать `repo-doctor --help` и объяснить read-only значение по умолчанию.
2. Выполнить `repo-doctor scan demo/broken-repository` и показать пять нарушений.
3. Выполнить `repo-doctor fix demo/broken-repository --dry-run`; обратить внимание, что
   файлы не созданы.
4. На заранее подготовленной копии выполнить `--apply`; показать список пяти созданных файлов.
5. Повторить scan: нарушений нет. Повторить apply: результат `[]`.
6. Показать JSON-отчёт и `config validate config.example.yaml`.
7. Показать `pr --provider github ... --dry-run`; подчеркнуть отсутствие сети и токена.
8. Показать итог pytest: 39 тестов и покрытие 89,72%.

Не выполнять реальный PR/MR, commit или push на защите без отдельного разрешения.

## Резервный сценарий без интернета

Интернет программе не нужен для scan/fix. Использовать локальный venv, wheel из `dist`,
копию `demo/broken-repository`, сохранённый протокол и презентацию. Интеграцию показать
через dry-run и mock-тесты. Если терминал недоступен, последовательно объяснить заранее
сохранённый вывод в протоколе.
