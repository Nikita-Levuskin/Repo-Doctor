# Вероятные вопросы комиссии и ответы

1. **Почему CLI, а не веб-интерфейс?** CLI проще интегрируется в локальную разработку и CI,
   не требует сервера и соответствует задаче аудита файлов.
2. **Почему Python 3.12?** Это актуальная версия с удобным `pathlib`, строгой типизацией и
   развитой экосистемой CLI и тестирования.
3. **Зачем Typer?** Он строит команды и справку из type hints и уменьшает служебный код.
4. **Зачем Pydantic?** Он строго проверяет структуру, типы и неизвестные поля конфигурации.
5. **Почему YAML и JSON?** YAML удобен человеку, JSON — автоматическим системам.
6. **Что означает идемпотентность?** Повторное исправление уже исправленного репозитория не
   создаёт дубликатов и не меняет существующее содержимое.
7. **Как предотвращена потеря данных?** Нужен `--apply`; перезапись выключена; есть dry-run;
   пути и symlink проверяются.
8. **Может ли программа выйти за корень?** Генерируемая цель проходит `resolve` и
   `relative_to`; выход или symlink-родитель отклоняется.
9. **Как распознаются бинарные файлы?** Файлы с NUL-байтом и превышающие лимит не
   декодируются как текст.
10. **Надёжен ли поиск секретов?** Нет, это эвристика с возможными ложными результатами;
    её задача — раннее предупреждение.
11. **Почему токены только в окружении?** Так они не попадают в код, конфигурацию и VCS.
12. **Почему не создан реальный PR?** Это внешнее изменение; задание прямо запрещает его
    без отдельного разрешения. Логика проверена mock-тестами.
13. **Что делает общий интерфейс провайдера?** Скрывает различия API и позволяет одинаково
    вызывать создание change request.
14. **Что проверено для HTTP?** Успех, отсутствие токена, 401, 403, 404, 409, 429, 5xx,
    тайм-аут, сетевой сбой и неожиданный payload.
15. **Почему покрытие не 100%?** 89,72% покрывает основные ветви; оставшиеся строки —
    преимущественно реальные CLI/API paths, избыточное покрытие не является самоцелью.
16. **Чем scan отличается от check?** Оба читают; check возвращает код 1 при error для CI.
17. **Какие манифесты поддержаны?** pyproject.toml, package.json, go.mod, Cargo.toml, pom.xml.
18. **Как добавить правило?** Реализовать функцию единой сигнатуры, зарегистрировать её и
    добавить тесты; для автофикса также цель и шаблон.
19. **Главное ограничение проекта?** Универсальные правила не учитывают все стандарты
    конкретной организации; нужна настройка или расширение.
20. **Достигнута ли цель?** Да: утилита реализована, собрана, установлена и проверена 39
    тестами; реальные API и другие ОС честно отмечены как не проверенные фактически.
